## 1. 运行链路摘要

导演台不是主对话框里的一个技能。主对话如果被判成「导演指令」，只会回一句「请到导演台底部的导演对话条」，自己不干活（`ui.py` 里这套闸门）。导演台有自己的页面、自己的对话、自己的工程文件夹。

从点进去到出片，真实顺序是这样的：

```
填主题
  →（非口播）先弹「需求理解卡」，确认后才开写
  → ① 写剧本，停住，等人改、点「采用」
  → ② 抽角色、画三视图（口播跳过）
  →（可选）抽跨镜道具 / 场景资产
  → ③ 拆分镜表，停住，等人改、点「采用」
  → ④ 按分镜写关键帧提示词并生图（口播跳过；默认先弹出预审）
  → ⑤ 按分镜写视频提示词，一镜一镜生视频（默认再预审一次）
  → ⑥ 用 ffmpeg 把已有片段接成成片，可另存 / 导出工程 / 打素材包
```

步骤名字写死在 `director_panel.py`：

```text
STEP_LABELS = ["主题", "剧本", "人物", "分镜", "关键帧", "生成", "合成"]
```

要点：

1. **不会自动一口气跑完。** 剧本、人物、分镜、关键帧、片段，每一步生成完都停下来。往下走必须点「采用」，或在底部对话里说「采用 / 继续」（走同一个函数）。
2. **同一时间只跑一个导演任务。** `director_busy` 为真时，再点生成、改镜、回滚都会被拒绝。这是防两套生成同时改同一份工程。
3. **点「停止」只取消当前这一轮**，不删已经写好的剧本和分镜。设计意图是停完还能单镜重试。文本步骤（写剧本、拆分镜）本身不看取消标志，见第 2 节。
4. **关软件可以续。** 进度写在工作区的 `director_session.json`。下次打开顶部会出现「继续 / 放弃」。视频如果已经提交到远端、本地还没下完，还会再问要不要只去查询、不要重新提交（避免再扣一次费）。
5. **成片成功后，这份续跑记录会被删掉。** 文件还在工程目录里，但下次打开导演台不会自动把这个项目装回来。
6. **底部导演对话和主对话隔离。** 不写主会话、不写长期记忆，只能调用 11 个 `director_*` 工具。面板上的「重写剧本」「重排分镜」其实只是把一句话预填进这个输入框，要你自己按回车才会真的发。

和外面三块的接线：

| 接线 | 实际怎么走 | 断没断 |
|---|---|---|
| 主对话 | 导演类句子被挡回去，不进主 Agent | 没断，是故意分开 |
| 生视频 / 生图 | 导演流水线直接调用 `tool_video_gen` / `tool_image_gen`，不经过主对话那道权限弹窗 | 没断。授权方式是你在导演台点按钮，不是主对话的确认框 |
| 导演对话里的工具 | 登记成「本地写入、半自动」。默认档位下**不弹**主权限窗，说了就执行 | 接线在，但和「生视频很贵」这个事实不匹配，见 P1-6 |
| 产物落盘 | 工程目录下分 `keyframes/`、`clips/`、`final/`，另有 `manifest.json` 记远端任务号 | 主路径在。交付物面板登记失败会被吃掉，只影响列表，不影响文件，见 P2-4 |
| 质检 | 只查关键帧静图，不查成片视频。没配视觉模型密钥时会放行，并标明「跳过 ≠ 通过」 | 接线在，能力范围窄，见第 3 节 |

口播（勾了「本人形象」）会抄近路：有照片就跳过人物三视图和关键帧，长文案还会被当成「原稿」原样切开。这是另一条控制流，不是同一条流水线少跑了两步那么简单，见 P1-1。

## 2. 逻辑问题清单

级别说明：

- **P0**：主路径上会让人以为停住了、或会弄丢已经生成的片子，而且界面还说得像没事。
- **P1**：常见操作下结果和界面说法不一致，或会多花钱、接不上。
- **P2**：能绕开，或只影响某一种看法，但会误导。

### P0-1　点「全部重新生成」会先把已有片段从项目里抹掉

**现象。** 已经生成了 6 镜里的 6 镜。点「全部重新生成」，再点「停止」，或中途有几镜失败。界面上旧片段变成「排队 / 失败」，合成时也找不到它们。

**证据。** 两处一起清：

- 界面先把每张卡片的路径清空（`director_panel.py` 的 `_regenerate_all`）。
- 流水线一进整批生成，第一件事就是 `self.clip_paths = [None] * len(self.shots)`（`video_pipeline.py` 的 `generate_all_clips`）。

单镜重生成会先把旧文件备份进 `versions/`。整批重生成没有这一步。磁盘上的旧 mp4 多半还在工程的 `clips/` 里，但项目状态不再指向它们，合成和卡片都只用 `clip_paths`。

**影响。** 一次「重来」加一次失败或停止，导演台里的成片素材等于丢了。要自己到文件夹里把文件捡回来，界面没有「恢复上一批」的入口。

**建议。** 新一轮整批生成开始前，先按单镜那套把旧路径放进版本栈；失败或停止时提供「恢复上一批片段」。至少不要在新文件落地之前就把旧路径写成空。

### P0-2　点了「停止」，界面会改口说「完成」或「出错」

**现象。** 逐镜生成时点停止。状态栏先出现「已停止，可直接重试」。几秒到几分钟后，这句话被盖掉，变成下面两种之一：

- 「逐镜生成完成：2/6 成功。可单镜改，或去合成。」没做完的卡片仍显示「排队中」，像还在等。
- 「出错：……」——当前这一镜的取消被当成异常。

**证据。**

- `_director_stop` 只把取消标志置上，并写「已停止」。它不改按钮、也不把这一轮收成「已取消」。
- 若取消发生在两镜之间：`generate_all_clips` 跳出循环，线程仍发出「逐镜生成完成」。`_on_clips_done` 无条件写成完成；没生成的镜还留在「排队」。
- 若取消发生在正在等的那一次视频请求里：视频接口按「取消」抛错，线程收成 `clips 异常：…`，`_on_error` 把阶段打成失败，状态栏写「出错」。
- 给导演对话的回执里，只要有错误标记，就优先报「失败」，「用户取消」被盖掉（`_set_busy` 里先看错误、再看取消）。

文本步骤更直白：写剧本、拆分镜、抽角色**全程不看取消标志**。点停止后，请求仍会跑完（文本接口超时可以到大约 240 秒），然后 `_on_story_ready` 把状态改成「剧本已生成」。按钮在此之前一直锁着，所以你会看到「已停止」，却什么都点不了，直到结果自己冒出来。

另外有一个很窄的窗口：整批视频一开始会 `begin_job()`，这一步把「已取消」清回未取消。如果停止点在线程刚启动、还没执行到这一行，这次停止会被清掉，整批继续跑，但对话回执仍可能记着「取消」。

**影响。** 停止不可信。人会以为已经停了、不会再扣费，结果请求还在跑；或者以为失败了，其实是自己按的停止。没做完的镜显示「排队」，看起来像卡死。

**建议。** 取消之后不要再发「完成」。没跑的镜标成「已停止」，不要留「排队」。文本步骤在请求返回后如果发现已经取消，就不要把结果写进编辑框，或者明确写「你已停止，结果仍在下面，采用与否由你决定」。`begin_job()` 不要无条件清掉「用户刚刚按过停止」。

### P1-1　口播里，主题写长了会被当成「逐字念的原稿」

**现象。** 勾了本人形象。主题框里写了一段超过 60 字的说明，比如「我想拍一个讲时间管理的口播，语气轻松，不要提产品名……」。系统不把它当选题，而把它切成几段原句去念。

**证据。** `_director_start_now`：口播且主题不少于 60 字，或用「原稿：」「直通：」开头，就设 `passthrough_script`，主题改成「本人形象口播（原稿直通）」。之后 `gen_story` 不再写文案，`gen_shots` 用 `split_voiceover_script` 只切段、不改写。占位提示里写过「≥60 字走直通」，但开始时没有再确认一句「我将按原文念，不改写」。

非口播没有这条近路。非口播会先出需求卡。

**影响。** 一段创作说明被当成台词。视频在念你的备注，而不是你要的口播稿。

**建议。** 只有明确前缀「原稿：」才直通。单靠字数不要切换。切换前用一句话问：「按原文念，还是按这个说明来写稿？」

### P1-2　需求理解失败时，会跳过确认卡直接开写

**现象。** 非口播点「开始导演」，本应先看到一张「我以为你要拍什么」的卡片，改完再确认。如果这一步模型失败、返回不是合法 JSON、或题材和叙事都是空的，卡片不出现，工程直接建起来，剧本开始生成。

**证据。** `understand_topic` 任何异常都返回空。`_open_understand_dialog` 收到空结果后写日志「跳过确认卡，直接按原流程开写」，然后调用真正的开工函数。状态栏有一行字，但没有「要不要继续」的按钮。点「开始导演」的人当时在等确认卡，不是在同意「理解失败也照写」。

**影响。** 对齐步骤在最需要它的时候消失，并立刻产生文本费用。主题被理解错时，没有最后一道人工闸。

**建议。** 理解失败就停在主题页，给出「重试理解」和「不看理解、直接开写」两个按钮。不要默认开写。

### P1-3　「旁白解说」没有真正的旁白

**现象。** 需求卡的声音可以选「旁白解说（后期配音）」。选完，片子里并不会多出一条旁白音轨。

**证据。** 三个选项是：`无台词（纯画面 + 字幕）`、`人物说中文台词`、`旁白解说（后期配音）`。落到面板时，只有第二项会打开「台词」开关。旁白只被写进项目规格的一段中文，让编剧在剧本里体现。后面的视频生成只在「台词开关打开」时把 `line` 交给模型念。没有配音、没有旁白轨。

原文使用里的「用原句作旁白念白」同样只是写给编剧的句子，不是一条音频工序。

**影响。** 人以为选了旁白片，出来的是带字幕的画面，或是角色自己在说话。规格文字和真实能力不一致。

**建议。** 卡片上写明「旁白目前只写进剧本，不会生成配音」。或者真的接一条后期配音，再允许这个选项。

### P1-4　分镜表上的「运镜」一栏，改了也不进视频

**现象。** 分镜生成后，「运镜」输入框常常是空的。你在这一栏补上「特写、缓慢推近」，点采用，真正发给视频模型的提示词里没有这句话。

**证据。** 生成分镜之后，`_enrich_shots_camera` 会把运镜拼进英文 `en`（如果英文里还没有镜头词），然后 `s.pop("cam")`，运镜字段被删掉。所以界面那一栏是空的。采用时 `_read_shot_rows` 会把你填的运镜存进分镜对象，但 `_build_clip_prompt` 只用 `en`，不读 `cam`。

模型如果已经在英文里写了 “shot” 这类词，轮转出来的运镜也不会再拼进去，同样被删掉。你看到的空栏，不代表这镜没有运镜，只代表运镜被藏进了英文句子。

**影响。** 分镜表有一列看起来能改、实际是摆设。人会以为自己改了机位，成片仍按旧英文拍。

**建议。** 采用时把运镜栏明确拼进该镜英文，或干脆不要单独一栏，让人直接改英文那一列。生成后如果运镜已经写进英文，就把那一句回填到运镜栏，不要留空。

### P1-5　有道具图时，上一镜的尾帧常常挤不进参考图

**现象。** 普通剧情片开了「尾帧接力」和「多参考图」。某一镜又有关键帧、角色正面、角色侧面、场景图、道具图。上一镜结尾的画面不会作为下一镜的参考。日志里可能有「缺：尾帧」，状态栏不说。

**证据。** 参考图最多 5 张（`AGNES_MAX_REF_IMAGES = 5`）。装配顺序是：关键帧 → 角色正面 → 主角侧面 → 场景 → 道具 → **才是尾帧**。满 5 张就不再加。口播模式已经把尾帧提前到关键帧后面，注释写明了旧问题是「背景中途换一小会」。剧情片没有做同样的提前。

一旦有参考图，首帧锁定会被关掉（`first_frame = None`），连贯完全指望这 5 张参考图。尾帧被挤掉之后，同一场戏的下一镜只靠文字说「接着拍」。

**影响。** 道具越认真锁，动作越容易在切镜时跳一下。这和产品自己写的「同场尾帧接力」相反，而且只出现在日志里。

**建议。** 剧情片在「同一场景」时，给尾帧留一个固定名额，挤掉的应该是次要侧面或重复道具，而不是连贯帧。状态栏用一句话说明本镜参考图缺了什么。

### P1-6　关掉「Prompt 预审」后，对话里一句「继续」就会开始生视频

**现象。** 底部对话说「采用，继续」。若当前停在关键帧或分镜，下一步就是生图或生视频。预审勾着时，还会弹出草稿让你点「按此生成」。预审一旦关掉，这次确认直接烧钱。主界面那套「这个工具要不要执行」的确认框不会出现。

**证据。** `director_revise_clip`、`director_confirm`、`director_merge` 等都登记为本地写入，档位是半自动（`risk.py`）。半自动在自动模式和普通交互模式下都是「可直接执行」，不需要再点确认。导演页面自己调用生视频函数，也不走 `exec_tool` 那道闸。预审默认是开的（`director_preview` 默认勾选），所以默认路径还有一道人确认。关掉之后，对话工具没有第二道闸。

面板上亲手点「采用」可以算你同意。对话模型替你选了「整批关键帧」时，系统提示虽然写了「整批很贵，宁可多问」，但这只是提示，不是程序强制。

**影响。** 预审关闭、或模型把「改一下」理解成整批重做时，会直接产生视频费用，而主权限设置看起来像「这些操作应该问我」。

**建议。** 把「重生成视频 / 整批关键帧 / 采用并进入生成」标成必须确认，不要跟「改一句剧本」放在同一档。预审关掉时，进入生视频前仍保留一次「将生成 N 镜，确认？」

### P1-7　续跑会忘掉两样你已经定过的事

**现象一。** 你改完剧本或分镜表，还没点采用，就关掉软件。下次「继续」，看到的仍是改之前的稿子。

**现象二。** 你关掉了「AI 智能分镜」，让它严格按 4 镜来。续跑之后，这个开关回到默认开启。再让它重拆分镜时，它又自己决定镜数。

**证据。** 退出时 `main.py` 会调用 `_save_session`。存的是流水线里的 `story` / `shots`，不是编辑框和分镜表上还没点采用的内容。采用函数才会把编辑框写回流水线。

`smart` 有写进 `prepare()`，但会话 JSON 的参数里没有这个字段，恢复时也不读。流水线上没有这个属性时，后面一律按「智能分镜开着」处理（`getattr(self, "smart", True)`）。界面上的勾选也不会被恢复，还是默认勾上。

质检状态 `qc_status` 同样没进会话。`review_notes` 在。续跑后，关键帧卡片的质检徽章会空，像没查过，尽管上次查过。

**影响。** 「继续上次」不等于「继续我屏幕上那一版」。智能分镜的选择在重开后悄悄变掉，后面的镜数和时长都会变。

**建议。** 存盘时带上编辑框原文、分镜表原文、`smart`、质检状态。退出前如果编辑框和已采用稿不一致，问一句要不要保存未采用的修改。

### P1-8　智能分镜打开时，需求卡上的镜数不算数

**现象。** 需求卡里把镜头数改成 4。确认开写之后，剧本和分镜仍按「通常 6～18 镜，纪录片可到 24」来写。分镜出来后，上面的数字框会被改成实际镜数。

**证据。** 智能模式的剧本提示（`_gen_story`）不提你填的镜数，只说让模型自己定。分镜提示同样是「通常 6～18」。工具提示写数字框在智能模式下只是「兜底默认」。需求卡却把镜头数当成一项可以改的需求，确认后写进面板，看起来已经生效。

关掉智能分镜时，提示仍是「约 N 个」，纪录片还可以加到 `max(N, 12)`。工具提示写的是「关闭时严格按此数拆分」，和提示词不一致。

**影响。** 你在确认卡上定的篇幅会被模型改掉，而且没有一句「你要 4 镜，我打算写 12 镜」。

**建议。** 智能模式也把「用户指定镜数」写进提示，并规定只能在一个窄范围内偏离，偏离了要在状态栏说明。关掉智能模式时，提示改成「必须 N 镜」，不要再写「约」和「可增加」。

### P2-1　阶段名（idle / running / done / error）不代表你看到的步骤

`DirectorPhase` 的注释写明它不替代现有运行状态。一点生成，阶段就被设成 running。片段全部成功不会改阶段；只有合成成功才变成 done，异常或合成失败才变成 error。部分镜失败仍可能留在 running。界面步骤条看的是 `director_step`，不看这个阶段。拿它做判断会误判「还在跑」或「已经完了」。

**建议。** 要么让它跟着真实步骤更新并显示，要么不要再当成状态机用。

### P2-2　口播跳过的步骤，步骤条仍显示成「已完成」

口播采用剧本后直接到分镜（步骤 3），采用分镜后直接到生成（步骤 5）。`_set_step` 把当前步之前的格子都涂成完成。人物和关键帧没做，看起来却像做过。

**建议。** 跳过的格子用「跳过」而不是绿色完成。

### P2-3　步骤条不能点，采用之后回不到上一页

步骤是标签不是按钮，内容区是一次只显示一页的栈。到了分镜页，剧本编辑框还在内存里，但页面上看不见，也没有「返回剧本」。要改只能用底部对话整段重写，而不是改你已经写好的那几句。

**建议。** 步骤条可点击，至少允许回看已经完成的页，不要因此重跑。

### P2-4　成片进交付物列表失败时没有声音

合成成功、文件也在。往主交付物列表追加时如果出错，代码直接忽略。导演台自己的播放按钮仍可用，主界面的交付物区可能没有这条。

**建议。** 登记失败写进导演日志，不要空过。

### P2-5　合成允许缺镜，两处说法相反

有镜失败时，给对话的回执写「不可直接合成」。界面状态却写「或去合成」。合成函数会跳过空镜，成功消息里会写「N/M 镜，缺 X 镜」。能合成是故意的，两句提示互相打架。

**建议。** 统一成：「可以合成，但缺 X 镜，成片会跳过它们。」对话不要说「不可合成」，除非按钮真的不可用。

### P2-6　成片一旦成功，续跑记录被清掉

`_on_merge_ready` 成功分支调用 `_clear_session`。当时内存里的项目还在，可以继续改。关掉软件再开，没有「继续」条。工程文件夹还在，导演台不会把它装回编辑器。

**建议。** 成片完成后仍保留会话，横幅改成「上次已出片，可继续改」，不要只在未完成时才能续。

### P2-7　对话系统提示把「重写剧本」说成不花钱

`director_chat.py` 的系统提示写「重写剧本 / 重排分镜：纯文本，不花钱」。实际仍调用 Agnes 文本接口，会计入文本额度。生视频才是大头，但「不花钱」是错的。

**建议。** 改成「不生图、不生视频，仍会调用文本模型」。

### P2-8　视频服务熔断时，失败原因会建议去写 HTML 动画

`tool_video_gen` 连续失败两次后，返回的句子里有「建议改用代码/HTML 动画方案」。这句话是给主对话准备的。导演台会把它当成这一镜的失败原因显示出来。导演台用户无法在这里改去写网页动画，这句话只会让人以为产品坏了或在说别的任务。

**建议。** 导演台路径使用自己的失败文案：哪一镜、什么错误、能否重试，不要带主对话的替代方案。

## 3. 剧本 / 分镜 / 提示词「水平」

打分是「这套提示词和规则，能稳定做出什么」，不是某一次模型抽风的分数。对照的是短视频常见做法：一件事讲完、镜头能拍、提示词能执行、风格和人物别变、时长和台词对得上。

总的天花板：**60～90 秒、单主角、场景不多的微故事，结构是够用的。** 它知道要忠于主题、要有起承转合、要锁人物和道具、要把镜头写成能画的英文。短板也集中：剧本没有范例、没有人检查结构；分镜的方法论只作用于「拆分镜」那一次；真正送给视频模型的句子是后来拼出来的，还会把方法论里禁止的词再加回去。没有「写完自己挑一遍毛病再改」的循环，只有关键帧静图的视觉复查。

### 3.1 剧本　6 / 10

**优点。**

- 角色定得清楚：编剧，不是分镜师。剧本用中文写发生了什么，明确不写镜头语言。这是对的分工。
- 有硬约束：必须留住主题里的体裁、人物、时代、原作；要有时间线和起承转合；人物只能是人或拟人活物；结尾单独列「关键道具」，避免酒壶被当成角色。
- 开工前有需求卡，把题材、叙事方式、原文怎么用、声音形式写进全片规格。规格会跟着剧本、分镜、角色、道具一起走。
- 口播是另一套提示：只写第一人称说的话，并按「每秒大约 4～5 个汉字」估算字数。这条是认真对过时长的。

系统提示很短，全部约束都在用户提示里。核心是这几句（`video_pipeline.py` 的 `_gen_story`）：

```text
你是专业的短视频编剧。你的任务：严格按用户给的主题创作一部微故事剧本。
主题已经限定了体裁 / 人物 / 时代 / 原作……不得替换成另一个故事。

1) 忠于主题……
3) 有清晰的时间线与起承转合：开头建立情境→中间发展/冲突→结尾收束；
5) 逐镜用一两句话描述这一镜发生了什么（不要写镜头语言或英文）；
```

**短板。**

- **没有范文。** 分镜有一条好例子和一张负面清单，剧本没有。模型只看到规则，看不到「一篇合格的 8 镜微故事长什么样」。同样的规则，强模型和弱模型差得会很大。
- **没有结构检查。** 写完不看是否真有转折、人物外貌是否前后一致、道具是否前后叫同一个名字。空稿、跑题、注水，只要接口没报错，就会进编辑框。
- **篇幅和镜数是软的。** 见 P1-8。智能模式甚至不把你要的镜数写进提示。
- **视觉信息偏少是设计使然，但后面补不稳。** 剧本被要求不写镜头。人物外貌只有「一两句」。后面靠另一次模型抽取英文外貌。抽取失败时的兜底是「the main character described in the script」——等于没锁。
- **温度 0.7，只生成一次。** 偏发散，又没有「不合格就按意见重写」的自动轮次。重写完全靠你在对话里再提。

**和常见短视频剧本比。** 单主角治愈、小故事、诗词意境、单人口播，这套够用，而且「不许另起炉灶」写得很硬，这是它的长处。系列感、多线、反转密度、信息密度（知识口播的要点清单）、每场只干一件事的场次表，都没有模板。它更像「把一句话扩成顺序事件」，还不是「按秒数排的拍摄剧本」。

### 3.2 分镜脚本　6.5 / 10

**优点。**

这是三条里写得最认真的。`SHOT_DIRECTOR_SYSTEM` 把一条视频提示词拆成三段，并写了短视频里真正会翻车的规则：

```text
① 主体：谁/什么，带可辨识的外观细节……不要只写「一个男人」
② 动作：一个能在该镜时长内演完的具体动作……不写心理活动、不写对话内容
③ 环境+镜头：场景与光线……再挂上镜头语言
· 单镜单一动作：4~6 秒只够一个动作……塞进一句里，视频模型只会演第一个或直接崩
· 同 scene 内必须能首尾帧接力：上一镜的结束状态≈下一镜的起始状态
```

英文栏还有一条完整范例和负面清单（`SHOT_EN_SPEC`）：

```text
✅ 好例子：'a young woman in a washed denim jacket, slowly raising a steaming
   ceramic mug toward her lips, warm morning light from a window on her left,
   soft shallow depth of field, medium shot, slow push-in, eye-level'
❌ 不要空泛形容词（beautiful / stunning / cinematic / amazing）
❌ 不要写 then / cut to / 然后
❌ 不要写画面内文字、字幕、水印
❌ 不要写抽象情绪和剧情背景
```

另外还有：景别 / 运镜 / 机位词表、场景编号（同场才接力）、每镜 4～12 秒、台词必须纯中文且 30 字以内、英文缺失时不许把中文字幕直接当画面提示词。这些都是踩过坑之后加上的，方向对。

**短板。**

- **范例只有一镜，没有一整组分镜。** 模型知道「一镜怎么写」，不知道「8 镜怎么起伏」：哪里该远景建立、哪里该反打、哪里该空镜收。相邻镜「结束状态接得上」只是一句要求，没有程序去对上一镜和下一镜的主体、朝向、光线。
- **运镜会按序号轮转。** 模型没写镜头词时，用镜号取景别、运动、机位，保证相邻镜不一样。词表里有甩镜、航拍、荷兰角。安静对话镜可能被轮到甩镜。这是「看起来有变化」，不是「按内容选机位」。
- **台词长度和镜长对不上。** 分镜要求台词 30 字以内。中文口播大约每秒 4～5 字，30 字大约 6～7 秒。智能模式却允许单镜 12 秒。口播文案那条已经按秒数算字数，对白分镜没有。长镜会念完一句就空着，或模型自己加动作。
- **中英两栏没有对照检查。** `zh` 是字幕，`en` 是画面。没有规则检查它们是不是同一件事。常见翻车是字幕在说 A、画面提示词在演 B。
- **解析很脆，失败就整段重来。** 只接受 JSON 数组。模型多说两句解释，或截断，就变成「分镜解析为空，请重试」。没有「剥出 JSON 失败后再要一次纯 JSON」的自动重试。
- **运镜栏和真正使用的英文脱节。** 见 P1-4。人在表上改的，不是模型最后看见的。

**和常见分镜表比。** 字段够一张能拍的表：画面、字幕、台词、场景号、时长、景别。缺的是行业表里很有用的三列：**上一镜结束时画面里有什么、这一镜开始时必须已经有什么、这一镜结束时要留住什么。** 现在这三句被要求写进英文散文里，模型一忙就会忘。可拍性（一镜一个动作、不要剪辑词、不要屏上字）写到了 7 分以上的意识；节奏和镜与镜的衔接还停在「提示里提过」。

### 3.3 分镜提示词（真正送给生图 / 生视频的那一段）　6 / 10

这里要分开看。方法论是在「拆分镜」时注入的。关键帧和视频用的是另一段拼接。

**视频提示词实际是：**

```text
英文 en
+ 画风句子（如水墨、电影感）
+ [CHARACTER LOCK] 角色外貌必须每镜一样
+ 道具锁定（有才加）
+ [PROJECT SPEC] 风格 / 机位 / 禁止项
+ [REFERENCE IMAGES] <Picture 1> 是开场帧，<Picture 2> 是角色……
```

对应代码是 `_build_clip_prompt` 和 `_build_ref_caption`。参考图指代写得具体，这是加分项：哪张图锁脸、哪张图锁场景、哪张图是上一镜尾帧，都用 `<Picture N>` 点名。人物三视图和场景图会尽量塞进最多 5 张参考图。这是目前保住「同一个人、同一个地方」的主要手段，比只在文字里说「保持一致」强。

**关键帧提示词实际是（`_build_keyframe_prompt`）：**

```text
Keyframe and environment concept art for ONE video shot: {那镜的英文}.
{人物锁} {修改意见}{质检改写}
High detail, cinematic composition, consistent lighting and visual style,
no text, no watermark, no extra characters.
```

**优点。**

- 预审窗口默认打开，你改的草稿和真正送去生成的是同一段代码，不会「看见的是 A、烧掉的是 B」。
- 英文缺失时，会用中文旁白另请模型写一句英文画面，写失败才用中性句，并打日志。不会再把字幕原文塞给视频模型去念。
- 关键帧有视觉复查：对一下人物、场景、多肢和乱字。不通过就把意见塞回提示重画，最多再试 2 次。仍不通过也留下最后一张，不把流水线卡死。没密钥或调用失败会标明跳过，不假装通过。
- 台词不进画面提示词，改由单独参数念，避免念出乱码。混英文的台词会先改写成中文。

**短板。**

- **方法论没有跟到最后一公里。** 三段式、负面清单、那条马克杯范例，只出现在拆分镜的系统提示里。关键帧模板自己又写了 `cinematic`，而这正是 `SHOT_EN_SPEC` 禁止的空泛词。画风表里的写实风格也带着 “cinematic live-action, 8k”。模型刚被教会别用这种词，拼接阶段再加回去。
- **没有针对提示词的改写器。** 视频提示词不再过一遍「是不是一个动作、有没有外观、有没有和锁词打架」。弱的 `en` 会原样进入视频模型。缺英文时的补写提示更短，只要「一句英文」，不再要求三段式。
- **中性兜底几乎不能拍：** `cinematic scene, continuous visual, no text overlay`。日志有警告，但生成会继续，这一镜和剧本无关。
- **质检不覆盖视频，也不覆盖提示词文本。** 静图过了，视频仍可能换脸、换背景、把一个动作演成两个。行业里常用「首帧 / 尾帧再看一眼」或「提示词规则打分后再提交」，这里都没有。
- **参考图 5 张上限会拆掉接力**，见 P1-5。文字上要求首尾相接，图片槽位却把尾帧挤掉。
- **锁词是英文外貌句子，不是始终带着三视图的每一面。** 正面优先，侧面只有余额才给。转头、背面仍然容易漂。三视图提示里还有 “even studio lighting” 和 “neutral background”，画风句附在后面。水墨片的人物设定图仍可能被画成棚拍真人，再去污染后面每一镜。v4.151 已经把画风补进三视图，冲突句还在。
- **预审框每镜只有大约三行高。** 一条完整提示词（英文 + 锁 + 规格）通常更长，不滚一下看不到后半，容易以为自己看过了全文。

**和常见可执行提示词比。** 一条能用的视频提示词一般固定为：主体外观、一个动作、场景光线、景别和运镜、风格、不要什么、时长、起始画面。这套在「拆分镜」时把前半讲清楚了，在「真正提交」时变成拼接，顺序和用词不再受那套方法论约束。所以分镜脚本的上限高于最终提示词的上限。人如果在预审里自己改，可以拉回来；不改的话，模型发挥到哪，片子就到哪。

### 3.6 三块对照

| | 剧本 | 分镜脚本 | 最终提示词 |
|---|---|---|---|
| 有没有范文 | 没有 | 有一镜好例子 + 禁止项 | 关键帧没有；视频沿用分镜英文 |
| 有没有结构 | 起承转合，写成要求 | 三段式 + 场景号 + 时长 | 拼接，没有再检查 |
| 失败怎么办 | 报错，等人重写 | JSON 失败整段重来 | 关键帧质检可重画 2 次；视频只重试网络错误 |
| 最强的地方 | 不许跑题、分出人和道具 | 一镜一动作、能画的英文 | 参考图逐张点名用途 |
| 最弱的地方 | 没有范例、不自检、镜数软 | 镜与镜衔接只靠自觉；运镜栏是空的 | 禁止词被拼回去；尾帧会被挤掉 |

## 4. 若要改，先改这 5 件

仍然只是建议，这次没有改代码。

1. **让「停止」说真话，并停止后还能看见旧片段。**  
   先做 P0-2 和 P0-1。停止后的状态只能是「已停止，完成了几镜」；整批重做之前先记住旧片段。这两件不改，后面调提示词的人无法判断是模型差还是流程把结果弄丢了。

2. **采用之前，把人改过的字真正用起来。**  
   运镜栏写入该镜英文（P1-4）；未点采用的剧本和分镜表写入续跑文件；`AI 智能分镜` 开关一起存（P1-7）。否则界面上的编辑是假的。

3. **开口播和开写之前，不要替用户做不可逆选择。**  
   超过 60 字不要自动当原稿（P1-1）。需求理解失败不要直接开写（P1-2）。「旁白」要么真做，要么在卡片上写「不会生成声音」（P1-3）。智能分镜必须看见你填的镜数（P1-8）。

4. **参考图给尾帧留座位。**  
   同一场景的下一镜，5 张里固定一张是上一镜结尾（P1-5）。这比再加一段「请保持连贯」的提示词有用。连贯是现在剧情片最明显的画面问题来源。

5. **让最终提示词服从已经写好的方法论，并加一次文本自检。**  
   关键帧模板去掉 `cinematic` 这类被负面清单禁止的词。提交前用同一套三段式检查：缺主体外观、多于一个动作、出现 then/cut、出现屏上文字，就自动改写一次再给人预审。剧本补 1 篇 8 镜范文，分镜补 1 组「远景建立 → 中景动作 → 特写反应 → 同场承接」的完整例子。不要先换模型。现有注释已经判断过：同一句话换模型仍弱，是提示词缺方法，不是模型不够。方法已经写在拆分镜那一步，缺的是把它用到最终字符串上，并用一张完整分镜而不是单镜来教。

不建议先做的：把 `DirectorPhase` 再扩成一套新状态机（P2-1，它现在几乎不驱动界面）；或在没修好停止和旧片段之前，加大自动重试次数。重试越多，P0 里那种「以为停了其实还在跑、旧片子还被清掉」越贵。
