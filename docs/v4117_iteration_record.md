> 迭代主题：交付物卡片 tooltip 黑底看不清修复

## 一、问题来源

拉起 v4.116 新包实测后截图反馈：**交付物卡片悬停 tooltip 是黑底灰字，浅色界面里看不清字**。

v4.116 刚给卡片补了 tooltip（显示完整路径 + 文件名），功能有了但样式塌了——Qt 走了系统默认 tooltip 皮肤。

## 二、根因定位

排查链路：

1. `ui.py` L5465 —— 卡片 tooltip 设置代码正常：`card_item.setToolTip(f"{rel}\n{name}")`；
2. `ui.py` L1755 —— **主窗口样式表里其实早就写了浅色 QToolTip 规则**（白底深字）；
3. 结论：命中 Qt 经典坑——**tooltip 是独立顶层窗口，不继承 QMainWindow 的 setStyleSheet**。主窗口级规则对 tooltip 无效，tooltip 一直走系统默认黑底灰字。

也就是说规则早就写了，只是挂在错误的层级上，从未生效过。

## 三、修复方案（双层保险）

| 层 | 文件/位置 | 内容 | 覆盖范围 |
|----|-----------|------|----------|
| ① 应用级 | main.py（QApplication 初始化后） | 全局 QToolTip 规则：白底 `#FFFFFF` + 深灰字 `#1F2937` + 浅灰描边 + 圆角 | **全部 tooltip**，含顶栏按钮悬停提示（它们之前也是黑底） |
| ② 控件级 | ui.py dvCard 样式表 | 同款 QToolTip 规则挂到卡片自身样式表 | 交付物卡片兜底（控件级样式会传给自己的 tooltip） |

应用级为主、卡片级兜底——将来即使某个窗口覆盖了全局样式，交付物卡片也不会漏。

## 五、过程踩坑记录（供后续复用）

1. **冒烟脚本两次返工**：
   - 第一版断言引用未定义变量（THEME_CARD）→ 修正；
   - 断言「应用级规则真实生效」时，冒烟脚本自建的 QApplication 和 main.py 的不是同一个 → 改为验证源码 + 控件级兜底即可；
   - 断言选错卡片（第一张 dvCard 是已有旧交付物）→ 改为遍历所有卡片匹配目标文件名。
2. **PYZ 验证脚本坑**：walk 收集器写进内联命令时闭包捕获外层 strs，第二个 set 永远是空集 → 假阴性。**每个目标模块要独立的 (set, walk) 闭包对**。
3. **main 模块位置**：main 在**外层 CArchive（scripts 段），不在 PYZ**。`pkg.extract('main')` 返回 bytes，需 `marshal.loads` 反序列化成 code 对象再遍历。
4. **打包沙箱坑**（v4.116 已踩、本轮沿用）：bash 跑 build_safe.py 会被沙箱拦 dist 写入（PermissionError），必须免沙箱前台跑。
